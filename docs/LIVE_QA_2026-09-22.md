# Live product QA — September 23, 2026 (through PR #20; PR #23 pending)

Target: https://porygen.vercel.app

## Final verdict

**Working MVP.**

The first QA pass correctly found that the real scanner was not connected to the customer-facing site. That blocker was fixed after the initial report.

The production product now exposes the validated Source Search V2 engine at `/scan` with no account required.

## Initial blockers found

The first live pass found:

- Scan CTA routed into disabled Supabase signup;
- direct SPA routes returned 404;
- Source Search V2 remained isolated under `labs/`;
- only the fictional demo was usable end to end.

PR #5 fixed SPA deep-link routing and the merged test-runner conflict.

Subsequent work then connected the real scanner to production.

## What changed

- `/scan` added as the real public scanner.
- All primary Scan CTAs point to `/scan`.
- `api/scan.mjs` exposes Source Search V2 through Vercel.
- Public scanning does not require Supabase auth.
- GitHub source fetching uses three REST calls for metadata/commit/tree and raw GitHub content for files.
- The V2 reference index is bundled with the serverless function.
- Strong findings require source-specific evidence.
- Possible/common patterns are secondary to strong findings.
- Review/dismiss/rescan works in the public flow.
- SPA deep links work.

## Founding-repository regression hardening

Later live testing found three narrower production regressions rather than an architectural failure:

1. conventional one-line/common code could be promoted too aggressively without stronger source-specific evidence;
2. a repository with zero eligible source files needed an explicit no-files-scanned state;
3. partial scans needed unmistakable incomplete-scope wording and unchecked-file reasons/counts where available.

PR #21 fixed all three and added focused regression coverage.

Final production smoke after merge/deploy:

| Case | Expected behavior | Result |
|---|---|---|
| Apex | normal production repository scan | **PASS** |
| `itsm-tier1-agent` | zero eligible files → **No eligible source files were scanned** | **PASS** |
| PoryGen | partial scan → clear **Partial scan** scope/reasons | **PASS** |

## Source Match Report launch and all-public smoke

PR #20 was reconciled with current main and merged at production commit `117e4af`. The live scanner now creates a self-contained **Source Match Report** HTML export after GitHub, ZIP, or folder scans. Browser Print can save the report as PDF. The report preserves the same coverage, strong/possible finding, exclusion, empty/partial-state and limitation semantics as the scan UI.

A follow-up production smoke exercised all 30 public WGLewis0721 repositories through the live scan/report flow. Twenty-nine completed scans and downloaded HTML reports were verified against their visible outcomes. No strong findings were returned in that sample; that is not evidence of originality. Three scans were partial and three were completed zero-file scans.

The one production failure was `Obby-CyberTruck`, which has no commits. GitHub's commit endpoint returns HTTP 409 with `Git Repository is empty.` Open PR #23 narrowly maps only that explicit GitHub response into the existing zero-file scan path. Generic 409 conflicts remain errors. PR #23's focused tests/build and live adapter recheck pass, but the fix is not production until the PR is merged/deployed.

## Current conclusion

A normal user can now:

**open PoryGen → choose public GitHub, ZIP, or local folder → Scan → understand coverage → inspect source-match evidence → review/dismiss findings.**

The production result contract also distinguishes a real no-match from zero-file and partial-scan states.

Nothing currently known is fatal to that MVP flow.

## Remaining limitations

These are next-stage product limitations rather than MVP blockers:

- production serves a 1,000-file / 199-package subset of the larger offline corpus;
- connected private GitHub repositories are not supported yet;
- scans remain synchronously bounded by file/byte/time budgets;
- GitHub review/dismiss state is browser-local;
- uploaded-project results are intentionally non-durable;
- Source Match Report is live as a local HTML/Print-PDF export; hosted report history/private sharing are not built;
- production currently still returns a GitHub HTTP 409 for a repository with no commits; open PR #23 contains the narrow fix;
- no GitHub App/private repo monitoring or automatic PR/push checks;
- no production customer entitlement path.
