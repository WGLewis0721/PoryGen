## Causes and changes

1. `src/lib/supabaseClient.ts` requires both `VITE_SUPABASE_URL` and
   `VITE_SUPABASE_PUBLISHABLE_KEY` at build time. The live disabled-account notice
   proves the build lacks at least one. `feedRepository` also requires that client.
   Correct production configuration and backend verification remain outstanding.
2. Source Search V2 is isolated in `labs/source-search-lab`; its README explicitly
   says it does not change the production scanner. The root Vite build and app
   routes do not publish its UI/server. Merging it does not integrate it into the
   customer journey. This QA patch does not redesign that integration.
3. BrowserRouter paths had no Vercel SPA fallback. Added `vercel.json` and a real
   HTTP deployment regression covering direct links and asset content types.
4. `npm test` on the original main failed six suites because Vitest collected
   the lab's `node:test` files. Excluded the lab from Vitest and chained its own
   runner into `npm test`, preserving both suites.
