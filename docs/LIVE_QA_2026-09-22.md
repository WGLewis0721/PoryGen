# Live product QA — September 22, 2026

Target: https://porygen.vercel.app

## Final verdict

**Working MVP.**

The first QA pass correctly found that the real scanner was not connected to the customer-facing site. That blocker was fixed after the initial report.

The production product now exposes the validated Source Search V2 engine at `/scan` with no account required.

## Initial blockers found

The first live pass found:

- Scan CTA routed into disabled Supabase signup;
- direct SPA routes returned 404;
- Source Search V2 remained isolated under `labs/`;
- only the fictional demo was usable end to end.

PR #5 fixed SPA deep-link routing and the merged test-runner conflict.

Subsequent work then connected the real scanner to production.

## What changed

- `/scan` added as the real public scanner.
- All primary Scan CTAs point to `/scan`.
- `api/scan.mjs` exposes Source Search V2 through Vercel.
- Public scanning does not require Supabase auth.
- GitHub source fetching uses three REST calls for metadata/commit/tree and raw GitHub content for files.
- The V2 reference index is bundled with the serverless function.
- Strong findings require source-specific evidence.
- Possible/common patterns are secondary to strong findings.
- Review/dismiss/rescan works in the public flow.
- SPA deep links work.

## Human-style production retest

After deployment, real scans completed successfully on production:

| Repository | Strong matches | Files checked | Time |
|---|---:|---:|---:|
| `sindresorhus/yocto-queue` | 1 | 4 | ~1.0 s |
| `psf/requests` | 3 | 36 | ~2.6 s |
| `expressjs/cors` | 0 | 6 | ~1.0 s |

These checks proved that the production GitHub credential was valid and the public scan function was executing real repository scans.

## Current conclusion

A normal user can now:

**open PoryGen → paste a public GitHub repo → Scan → understand results → inspect evidence → take an action.**

Nothing currently known is fatal to that MVP flow.

## Remaining limitations

These are next-stage product limitations rather than MVP blockers:

- tiny reference corpus;
- public repos only;
- bounded scan size;
- browser-local review/dismiss state;
- no GitHub App/private repo support;
- no automatic PR/push checks;
- no paid entitlement path.
